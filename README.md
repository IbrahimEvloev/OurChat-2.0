# OurChat — запуск и тест с телефона

Важно: сервер должен запускаться на компьютере (у вас должен быть установлен
Node.js), а телефоны подключаются к нему как клиенты через локальную Wi-Fi
сеть. Запустить сервер прямо с телефона без компьютера не получится.

## 1. Установка (один раз)

1. Установите Node.js (если ещё не установлен): https://nodejs.org
2. Распакуйте архив, откройте терминал в папке проекта и выполните:
   ```
   npm install
   ```

## 2. Запуск

```
npm start
```

В консоли появится что-то вроде:

```
Сервер запущен на порту 3000
Открой с телефона (та же Wi-Fi сеть) по одному из адресов:
  http://192.168.1.25:3000
```

## 3. Проверка с телефонов

1. Убедитесь, что **компьютер и оба телефона подключены к одной Wi-Fi сети**.
2. На каждом телефоне откройте браузер и введите адрес из консоли
   (например `http://192.168.1.25:3000`).
3. На первом телефоне зарегистрируйте пользователя (например `+79261111111`),
   на втором — другого (например `+79262222222`).
4. На первом телефоне через поиск найдите второй номер и откройте чат,
   отправьте сообщение.
5. На втором телефоне зайдите в чат с первым номером — сообщение должно
   появиться сразу (в реальном времени, через сокеты).

Если телефон не может достучаться до адреса — скорее всего, брандмауэр
компьютера блокирует порт 3000: разрешите входящие подключения на этот
порт для локальной сети, либо временно отключите брандмауэр для теста.

## Что было исправлено

- **Сообщения не доходили до собеседника**: клиент не передавал свой номер
  в комнату чата (`chatId` строился только по одному числу), из-за этого
  каждый собеседник фактически сидел в своей отдельной комнате.
- **Список чатов был всегда пустым**: код ссылался на несуществующий
  `window.users` вместо использования ответа от `/search`.
- **XSS**: текст сообщений вставлялся через `innerHTML`; теперь используется
  `textContent`.
- **Пароли** теперь хранятся хешированными (bcrypt), а не в открытом виде.
- Добавлены проверки после `window.location.href` редиректов, чтобы скрипт
  не продолжал выполняться с пустыми данными.
- Добавлена кнопка «назад» на странице чата.

## Что стоит иметь в виду дальше

- Хранилище — только в памяти сервера (`users`, `chats`): перезапуск сервера
  стирает всех пользователей и переписки. Для реального использования нужна
  база данных.
- Нет токенов/сессий: клиент говорит серверу, кто он, и это принимается на
  веру. Для продакшена нужна нормальная авторизация (JWT/сессии + проверка
  на сервере, что сокет действительно принадлежит залогиненному номеру).
